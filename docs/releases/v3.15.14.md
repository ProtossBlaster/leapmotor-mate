# v3.15.14 — a two-car account can finish the setup wizard

This release answers [issue #280](https://github.com/ProtossBlaster/leapmotor-mate/issues/280).

## What changes

- The setup wizard accepts an account with more than one car. Until now it drew a card per car,
  each with its own pack list and PIN, and then refused the form with "Please select a battery
  variant first" — on a form where every pack had been selected. The check ran on the single-car
  field, which the multi-car branch never fills; the answers were posted in a different field. It
  now validates what is posted: every car must carry its own pack. The defect dates back to
  v3.13.0, the release that introduced the per-car cards, so every account with two or more cars
  has been blocked since.
- The account-wide capacity setting no longer falls back to 65.0 kWh on a multi-car install. It
  mirrors the first car's own answer, range-extender flag included. This setting is only the
  fallback for a car that has no capacity of its own; each car's pack was, and remains, stored per
  vehicle.
- A car of a model Mate does not recognise now gets the manual kWh field on its card, with the same
  hint the wizard already shows when a single unrecognised car is set up. Before, its card carried a
  heading and no options at all.

Local release verification passed **3,318 tests**, with **no skips**. Two of those are new and run
the wizard's own JavaScript, rendered from the real template, in Node: six scenarios covering two
cars through, the account-wide mirror, a car with no pack refused, its manual field accepted and
posted, the single-car path unchanged, and an empty form still refused. The wizard was also
exercised in a browser against a demo container for four cases — two cars, three cars with a
range-extender first, one car, and an unrecognised model — each checked against what the database
actually stored. Test data was synthetic and no live vehicle-cloud command was sent.

## Update and rollback

- Back up Mate using its existing backup feature before upgrading.
- Docker and Home Assistant use the normal image update while retaining the existing data volume.
- MateDesktop receives the payload through its existing updater; no new shell installer is needed.
- An installation that is already set up is unaffected: this release changes the first-run wizard.
- This release changes no database schema, stored data or MQTT entity and needs no migration.
- Rolling back to v3.15.13 requires no data conversion. A multi-car account is blocked again.

## Italiano

Chi ha più di un'auto sullo stesso account non riusciva a finire la configurazione iniziale. Il
programma disegna una scheda per ogni auto, con la sua batteria e il suo PIN, e poi rifiutava
l'invio dicendo «scegli prima una variante batteria» — su un modulo dove le batterie erano state
scelte tutte. Il controllo guardava il campo di quando l'auto è una sola, che nel percorso a più
auto non viene mai riempito; le risposte viaggiavano in un altro campo. Ora il controllo guarda
quello che viene spedito davvero: ogni auto deve avere il suo pacco. Il difetto esiste dalla
v3.13.0, la versione che ha introdotto le schede per auto.

Due correzioni minori nello stesso punto: la capienza generale dell'account non ripiega più sui
65,0 kWh che nessuno aveva scelto, ma riprende la prima auto (bandierina REEV compresa); e l'auto di
un modello che Mate non conosce riceve sulla sua scheda il campo per scrivere i kWh a mano, lo
stesso che il programma offre già quando l'auto non riconosciuta è una sola.

Cambia solo un template: nessuna modifica al database, ai dati salvati o alle entità MQTT. Chi ha
già configurato Mate non è toccato, perché si tratta della procedura di primo avvio. Docker, add-on
Home Assistant e MateDesktop ricevono il normale aggiornamento; il ritorno alla v3.15.13 non
richiede conversioni.
