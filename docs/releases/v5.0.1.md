# Mate 5.0.1 — a Home Assistant command keeps the car's PIN

A command sent from Home Assistant while Mate was saving a reading could go out with no PIN. The reading
saved at that moment could be lost as well.

---

## What changes

### A Home Assistant command no longer loses the car's PIN ([#495](https://github.com/ProtossBlaster/leapmotor-mate/issues/495), @chengler)

- Mate's poller keeps a single database connection, and two threads use it:
  - the poll loop, which saves every reading;
  - the MQTT thread, which runs a command from Home Assistant and reads the car's PIN for it.
- Nothing stopped the two threads from using the connection at the same moment. When they did, the
  database refused both with "bad parameter or other API misuse":
  - the command went out with no PIN and was refused with "Vehicle PIN is missing";
  - the poll loop lost the reading of that moment ("Frame processing failed").
- The poller now uses its database from one thread at a time. A command that arrives while a reading is
  being saved waits for that save, then reads the PIN.
- @chengler found the cause and described it exactly. It was reproduced on Mate's own code before the fix.

---

## Upgrade impact

- No schema change and nothing to do. The web part is unchanged.
- If you skipped 4.25.0, a security release, read [its upgrade impact](v4.25.0.md#upgrade-impact).

## Verification

- 2 new tests, both seen failing before the fix:
  - two threads never run a statement on the connection at the same time (before the fix: 359 times);
  - a PIN read 3,000 times while the other thread writes is always the car's PIN.
- The reproduction of #495 ran for 20 seconds each time:

  | Code | Commands with no PIN | Errors in the poll thread |
  |---|---|---|
  | 5.0.0 | 381 of 2,043,623 | 48 |
  | this release | 0 of 1,938,683 | 0 |

- Ran on a test install reading a real car: it became healthy, and its log shows no error.
- No command was sent to the car during these checks.
- Full suite in Docker on this release's code: 6275 passed, 7 skipped.

## Italiano

# Mate 5.0.1 — Un comando da Home Assistant tiene il PIN dell'auto

Un comando mandato da Home Assistant mentre Mate salvava una lettura poteva partire senza PIN. Anche la
lettura salvata in quel momento poteva andare persa.

## Cosa cambia

### Un comando da Home Assistant non perde più il PIN dell'auto ([#495](https://github.com/ProtossBlaster/leapmotor-mate/issues/495), @chengler)

- Il poller di Mate tiene una sola connessione al database, e due thread la usano:
  - il ciclo di lettura, che salva ogni lettura;
  - il thread MQTT, che esegue un comando da Home Assistant e legge il PIN dell'auto per farlo.
- Niente impediva ai due thread di usare la connessione nello stesso momento. Quando succedeva, il
  database rifiutava entrambi con «bad parameter or other API misuse»:
  - il comando partiva senza PIN e veniva rifiutato con «Vehicle PIN is missing»;
  - il ciclo di lettura perdeva la lettura di quel momento («Frame processing failed»).
- Ora il poller usa il suo database da un thread alla volta. Un comando che arriva mentre una lettura viene
  salvata aspetta che il salvataggio finisca, poi legge il PIN.
- @chengler ha trovato la causa e l'ha descritta con esattezza. È stata riprodotta sul codice di Mate
  prima della correzione.

## Impatto dell'aggiornamento

- Nessun cambio di schema e niente da fare. La parte web non cambia.
- Se hai saltato la 4.25.0, un rilascio di sicurezza, leggi [il suo impatto dell'aggiornamento](v4.25.0.md#impatto-dellaggiornamento).
