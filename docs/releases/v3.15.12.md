# v3.15.12 — OTA update notice in Home Assistant

This release answers [discussion #277](https://github.com/ProtossBlaster/leapmotor-mate/discussions/277).

## What changes

- Mate publishes a new `OTA Update Notice` binary sensor over MQTT, using the Home Assistant
  `update` device class, so an automation can react the moment a software-update message
  arrives in the Leapmotor account inbox.
- The message title and its send time travel with it as entity attributes. They are published
  together with the state, empty ones included, so a stale title never remains under an entity
  that is off.
- No additional cloud request is made. The poller already scans the account inbox every ten
  minutes for the Overview indicator, and the entity publishes that stored answer.
- Update detection is stricter, because the value now reaches a phone notification rather than
  only a web indicator. The previous scan matched bare substrings: `ota` matched inside
  unrelated words such as *nota* and *quota*, and a lone `upgrade`, `aggiornamento` or
  `mise à jour` matched membership offers and terms-of-service notices. Acronyms now match as
  whole words, and a generic update word only counts next to a software or vehicle word.
  Detection covers the eight languages a Leapmotor account may use.

## What the entity does not claim

- The inbox belongs to the **account**, not to a vehicle. On an installation with two cars the
  same notice is published under both VINs, which is what the Overview already shows for
  whichever car is selected. Attributing it to one car would hide it from the other.
- It reports that an update message exists, not that a specific vehicle has an update pending.
- It carries no version number. The vehicle cloud exposes no structured update status, no
  available version and no installed version, so none is invented.
- Detection remains a keyword match on the message text. It is deliberately a stopgap until a
  genuine update message is captured on a car and its message type can be used instead.

Local release verification passed **3,302 tests**, with **2 skips**. Sixteen of those tests are
new and cover the tightened detection in every supported language, the published state and
attributes, the account-level scope on two vehicles, and a malformed timestamp. Test data was
synthetic and no live vehicle-cloud command was sent.

## Update and rollback

- Back up Mate using its existing backup feature before upgrading.
- Docker and Home Assistant use the normal image update while retaining the existing data volume.
- MateDesktop receives the payload through its existing updater; no new shell installer is needed.
- The new entity appears through MQTT discovery when the poller reconnects after the update.
- This release changes no database schema or stored data and needs no migration.
- Rolling back to v3.15.11 requires no data conversion. The entity disappears from Home
  Assistant and the looser update detection returns.

## Italiano

Mate pubblica una nuova entità in Home Assistant, `OTA Update Notice`, accesa quando nella casella
dei messaggi dell'account Leapmotor c'è un avviso di aggiornamento software. Titolo e data del
messaggio viaggiano come attributi, ed è quanto basta a un'automazione per mandare una notifica.
Non viene fatta nessuna richiesta in più al cloud: la casella viene già letta ogni dieci minuti per
l'indicatore in Panoramica, e l'entità pubblica quel risultato.

Il riconoscimento dell'avviso è stato reso più stretto, perché ora accende una notifica e non solo
un'icona: prima confrontava sottostringhe, e `ota` combaciava dentro parole come *nota* e *quota*,
mentre `upgrade`, `aggiornamento` o `mise à jour` da soli combaciavano con offerte commerciali e
avvisi sulle condizioni di servizio. Ora le sigle combaciano come parole intere e una parola
generica di aggiornamento conta solo accanto a una parola software o veicolo, nelle otto lingue
supportate.

L'entità va letta per quello che è: la casella è dell'**account**, quindi con due auto lo stesso
avviso compare su entrambe, e dice che è arrivato un messaggio, non che quell'auto abbia un
aggiornamento in attesa. Non c'è nessun numero di versione perché il cloud non lo pubblica.

Non cambia lo schema del database e non vengono convertiti o cancellati dati. Docker, add-on Home
Assistant e MateDesktop ricevono il normale aggiornamento; il ritorno alla v3.15.11 non richiede
conversioni e toglie l'entità.
