# v3.17.1 — a wrong URL no longer locks you out of Settings

Reported by [@synvoll](https://github.com/synvoll) in
[#294](https://github.com/ProtossBlaster/leapmotor-mate/discussions/294): after a wrong Home Assistant
URL in the wallbox card, Settings would no longer open. With it, two smaller changes asked for or found
the same week.

## What changes

- **A wrong Home Assistant URL can no longer take over Settings.** When Settings opens, the wallbox card
  tests the connection to Home Assistant by adding `/api/` to the URL. With a URL that carries a path —
  a dashboard link, for instance — that request lands on Home Assistant's web page rather than its API,
  and Home Assistant answers with the page. Mate took that answer for a success and put the whole page
  into Settings, scripts included: the view became *Could not load Home Assistant*, and the field to
  correct the URL lived on that very page. Now a URL that answers with a web page is reported as **not
  the Home Assistant API**, with the base address to use instead, and nothing that comes back from the
  configured address is put into the page as code. That also closes a way for whatever answered at that
  address to run a script inside Mate.

- **A trip is kept from 200 metres, no longer from 500.** The threshold came in with v1.0.4 at half a
  kilometre, to match Home Assistant's `leapmotor_trip` integration, and it deleted shorter drives
  outright — a 330 m trip to the bakery disappeared from the kilometres and from the list. Below 200 m a
  movement is still a manoeuvre, such as moving the car to another space, and is still dropped. A short
  trip keeps its distance and shows no average consumption: over a few hundred metres a single step of
  the battery gauge would read as a consumption no car has.

- **A command left retained on the MQTT broker is no longer executed.** Mate subscribes to its command
  topics every time it connects, and a broker hands every new subscription the last *retained* message.
  Home Assistant sends its commands unretained, but anything else on the broker — a script, an
  automation publishing with retain — could leave one there, and Mate ran it again at every restart and
  reconnect: an unlock, a trunk, a climate start, wherever the car was. A command now runs only when it
  is sent; a retained one is logged and ignored.

## What does not change

No entity is renamed or removed, and the MQTT commands sent from Home Assistant work exactly as before.
The trip distance is still chosen the same way: when the odometer, which counts whole kilometres, steps
by one on a short movement, Mate still trusts the GPS track below half a kilometre, so a 330 m drive is
booked at 330 m and not at a full kilometre. Nothing already stored is changed; the database gains no
column.

## Verification

- The full suite passes: **3 410 tests**, and CI is green on the three commits of this release
  (`50acb6d`, `3ce43e4`, `6b79351`).
- Every test for new behaviour was **watched failing first**: four for the URL (plus a guard that a real
  Home Assistant answer still connects), three for the 200 m threshold (plus guards that the GPS rule
  and the missing average stay as they are), two for retained commands (plus guards that a live button
  and a live switch still run).
- The URL fault was reproduced through the real route with a local server answering like Home
  Assistant's web page, and then **tried in a browser** with the same wrong URL saved, on v3.17.0 and on
  this code side by side. On v3.17.0 the card said *Connected*, showed the Home Assistant page inside
  Settings, ran the script that came with it and renamed the browser tab *Home Assistant*. On this
  version the card says *Not connected*, shows the message pointing to the base address, the page stays
  whole and the URL field can be corrected in place.
- The way out for an install already locked out — clearing the saved URL from inside the container —
  was tried against the real database schema: before, the route injected the page; after, it shows the
  plain prompt to enter the URL and token.

No command was sent to any vehicle: every test drives a fake cloud client and a fake broker message.

## Update and rollback

- Back up Mate using its existing backup feature before upgrading.
- Docker and Home Assistant use the normal image update while retaining the existing data volume.
- Nothing to do after the update. An install already locked out of Settings by a wrong URL opens again
  on this version and shows what is wrong with it.
- Rolling back to v3.17.0 brings back all three old behaviours: a wrong URL can take over Settings
  again, a trip under 500 m is deleted when it ends, and a retained command runs at every reconnect.
  Trips between 200 and 500 m recorded on this version stay in the database: the older version only
  decides at the moment a trip ends, and does not revisit the ones already stored.

## Italiano

**Un URL di Home Assistant sbagliato non si prende più le Impostazioni** (#294, @synvoll). Aprendo le
Impostazioni, la card della wallbox prova la connessione aggiungendo `/api/` all'URL; se nell'URL c'è un
percorso — il link di una dashboard — la richiesta finisce sulla pagina web di Home Assistant invece che
sulla sua API. Mate prendeva quella pagina per un successo e la inseriva nelle Impostazioni, script
compresi: la schermata diventava «Could not load Home Assistant» e il campo per correggere l'URL stava
proprio lì. Adesso un URL che risponde con una pagina web viene segnalato come *non è l'API di Home
Assistant*, con l'indirizzo base da usare, e niente di quello che arriva da quell'indirizzo entra nella
pagina come codice. Provato anche nel browser, fianco a fianco con la v3.17.0.

**Un viaggio conta da 200 metri, non più da 500** (@michapr). I tragitti più corti venivano cancellati
del tutto: 330 m fino al panettiere sparivano dai chilometri e dall'elenco. Sotto i 200 m resta una
manovra e si scarta ancora. Un viaggio corto tiene i suoi chilometri e non mostra una media di consumo,
che su poche centinaia di metri sarebbe solo rumore. I viaggi già cancellati non tornano.

**Un comando MQTT rimasto «trattenuto» sul broker non viene più eseguito.** Home Assistant manda i
comandi senza trattenerli, ma qualunque altra cosa sul broker poteva lasciarne uno, e Mate lo rieseguiva
a ogni riavvio o riconnessione: uno sblocco, il bagagliaio, il clima. Adesso un comando parte solo
quando viene mandato.

Tornando alla v3.17.0 tornano tutti e tre i comportamenti di prima; i viaggi fra 200 e 500 m registrati
con questa versione restano nel database.
