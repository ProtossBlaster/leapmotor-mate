# v3.15.8 — merged-trip statistics and responsive bundle exports

One patch release combines the fixes for [beta #44](https://github.com/ProtossBlaster/MateBetaTesterOnly/issues/44)
and [beta #13](https://github.com/ProtossBlaster/MateBetaTesterOnly/issues/13).

## What changes

- Merged trips count once in Statistics and date-range totals, with their combined distance.
  In the reported example, coverage becomes 7 km instead of 1 km and locally computed energy
  becomes approximately 0.40 kWh instead of 0.06 kWh. A group belongs to its parent's start date.
- Encrypted research exports no longer perform blocking work on the web event loop.
  Preparation, busy, failure and download-started messages are translated into all eight languages.
  Repeated clicks do not start another export; another concurrent request receives HTTP 409.
- Export data stays associated with the original selected vehicle during sidebar changes.
- All existing archive sections, location redaction and encryption are retained. No cloud
  probes were removed and no timeout was shortened: a slow cloud can still delay completion.
- Web logs record elapsed seconds by stage and total time, without logging bundle contents.
  The encrypted metadata includes completed stages before the archive is sealed; the final
  archive/encryption stage and total are available in logs only.

## Statistics clarification

[Discussion #42](https://github.com/ProtossBlaster/MateBetaTesterOnly/discussions/42) describes
different coverage populations. Cloud-covered trips may include generator operation. The
Statistics REEV average uses measured battery-only **trips** when available, not an inferred
count of all kilometres driven electrically. Trips and Report retain their existing getEC
coverage basis. The merge correction does not make those distinct averages interchangeable.

## Update and rollback

Local release verification: **3,289 tests passed, 1 skipped** (a git-excluded local
documentation reference), with one existing Starlette/AnyIO deprecation warning.
This includes Chromium chart checks and the new real-browser bundle-download check.
Docker image build and encrypted-export runtime smoke test passed with network disabled;
Desktop payload dependency-contract verification passed. Test databases were synthetic,
and no live vehicle cloud requests were made during these checks.

- Back up Mate using its existing backup feature before upgrading.
- Docker: pull the updated image and recreate the container, keeping the same data volume.
- Home Assistant: install the normal add-on update when available; keep its existing data.
- MateDesktop: use the existing payload updater/restart flow. No new shell installer is needed.
- No dependency, database schema, stored settings or original trip segments change.
- Corrected totals on existing merged histories are expected, not loss of historical data.
- Rollback uses the prior v3.15.7 image/payload through the existing deployment mechanism.
  Since this release performs no schema migration, no data conversion is needed. The old
  calculation and export behavior return with the old version.

REEV and standard editions are **not unified** by this patch. Existing research gates remain.
The bundle slowdown reported by the tester has not been profiled on their actual device:
the web-blocking mechanism was reproduced locally, and instrumentation now makes the remaining
cloud/archive time diagnosable.

## Italiano

Un unico aggiornamento corregge le statistiche dei viaggi uniti (#44) e il blocco dell'interfaccia
durante la preparazione del bundle (#13). Il caso segnalato passa da due viaggi a uno,
con 7 km coperti e circa 0,40 kWh invece di 1 km coperto e 0,06 kWh.

Il bundle resta completo e cifrato. Durante l'attesa viene mostrato lo stato della preparazione;
i clic ripetuti non generano esportazioni aggiuntive. Il cloud può ancora richiedere alcuni minuti:
non sono state eliminate informazioni né abbreviati i timeout. I tempi delle fasi vengono
registrati nei log e, prima della cifratura, nei metadati del bundle.

È un normale aggiornamento per Docker, add-on e payload Desktop. Non cambia lo schema del
database, non cancella dati e non richiede una nuova app Desktop. Conservare il volume dati e
fare il consueto backup. Tornando alla versione precedente tornano anche i vecchi calcoli.
L'unificazione REEV/standard rimane fuori da questa release.
