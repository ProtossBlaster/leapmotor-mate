# v3.15.9 — B05 live-status path compatibility

This patch fixes [#278](https://github.com/ProtossBlaster/leapmotor-mate/issues/278).

## What changes

- The Vehicle page, manual Refresh, raw-signal diagnostics and charge-plan reader now share
  the poller's model-aware status-path behavior.
- A B05 first uses its reported model path. If that path is unsupported, Mate retries once
  through the `c10` family path and remembers the working choice separately for each VIN.
- The real vehicle model is never rewritten, so commands, capabilities, window scaling and
  battery sizing retain their existing behavior.
- B10, C10 and T03 reads that already work continue directly through their normal path.
- A fallback that also fails is not retried indefinitely or charged on every request.

The diagnostic bundle attached to #278 showed the poller successfully learning the `c10` path
while the independent web command client repeatedly requested the unsupported B05 path. The
same bundle contained 1,208 failed status reads and 76 failed charge-plan reads, each followed
by a session reset. The fix removes that difference between the two clients.

## Dependency and test maintenance

- Pillow is explicit in the web requirements. `leapmotor-api 0.3.1` does not expose the
  previously requested `image` extra, so relying on that extra did not guarantee Pillow in a
  fresh installation.
- AnyIO stays below 4.15 while this release remains on FastAPI 0.115.0 / Starlette 0.38.6.
  AnyIO 4.15 deprecated an alias still imported by that Starlette series.
- The research-bundle privacy test now matches complete numeric coordinate values, avoiding a
  false failure when a timestamp's seconds and microseconds happen to begin with `45.07`.

Local release verification passed **3,298 tests**, with **1 intentional skip** for a local,
git-excluded documentation reference. Deprecation warnings were treated as errors. Browser,
server, security, multi-vehicle, status-fallback and research-export tests were included. Test
data was synthetic and no live vehicle-cloud command was sent.

## Update and rollback

- Back up Mate using its existing backup feature before upgrading.
- Docker and Home Assistant use the normal image update while retaining the existing data volume.
- MateDesktop receives the payload through its existing updater; no new shell installer is needed.
- This release changes no database schema or stored data and needs no migration.
- Rolling back to v3.15.8 requires no data conversion. The B05 live pages will regain the old
  failure, but recorded trips and other stored data remain intact.

## Italiano

Questo aggiornamento corregge la lettura live sulle B05. Il poller sapeva già riprovare lo stato
del veicolo tramite il percorso `c10`, mentre la pagina Veicolo e la lettura del piano di ricarica
continuavano a usare il percorso B05 non supportato. Ora entrambe applicano lo stesso fallback e
ricordano il percorso funzionante separatamente per ogni VIN.

Il modello reale dell'auto non viene modificato e i percorsi già funzionanti di B10, C10 e T03
restano invariati. Non cambia lo schema del database e non vengono convertiti o cancellati dati.
Docker, add-on Home Assistant e MateDesktop ricevono il normale aggiornamento; il ritorno alla
v3.15.8 non richiede conversioni.
